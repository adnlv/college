# Завдання 4. HMAC-SHA256 та підміна повідомлення

1. зі свого варіанта візьміть HMAC-ключ (hex), вихідне та змінене повідомлення;
2. перетворіть ключ на bytes через `bytes.fromhex()`, обчисліть HMAC-SHA256 початкового повідомлення;
3. реалізуйте перевірку MAC через `hmac.compare_digest()`. Перевірте, що для початкового повідомлення збережений MAC коректний;
4. спробуйте перевірити змінене повідомлення зі старим MAC. Зафіксуйте результат;
5. обчисліть для зміненого повідомлення новий звичайний SHA-256 та поясніть, чому на відміну від HMAC це не захищає від навмисної підміни повідомлення.

## Результат виконання

```text
HMAC key (hex): 0d5552ceec77874c4079b42ffb324b86
Initial message: user=frank&operation=pay&amount=340&ref=06
Changed message: user=frank&operation=pay&amount=840&ref=06

Initial HMAC-SHA256: 426cd3ce7630be97389b143f4ff5ef5eaa5a77b0281c347b37082a758d120792

Verify initial message: True
Verify changed message with initial MAC: False

Changed message SHA-256: 6a1c25c76f5cdf8b465000a35ed4fce50613f5acc84bb499246c368e1e660c07
```

## Пояснення

Звичайний хеш SHA-256 є публічною детермінованою функцією без секретного ключа (unkeyed cryptographic hash function). Будь-яка особа (зокрема зловмисник, що перехопив канал передачі):

1. Може змінити вміст повідомлення (наприклад, замінити `amount=340` на `amount=840`).
2. Самостійно обчислити новий валідний SHA-256 хеш для підробленого повідомлення (`6a1c25c76f5cdf8b465000a35ed4fce50613f5acc84bb499246c368e1e660c07`).
3. Надіслати отримувачу сфальсифіковане повідомлення разом із новим хешем. Одержувач, перевіривши відповідність хешу повідомленню, зафіксує збіг і вважатиме повідомлення коректним, оскільки звичайний хеш підтверджує лише відсутність випадкових пошкоджень у каналі, але не автентичність джерела.

На відміну від SHA-256, HMAC (Hash-based Message Authentication Code) використовує спільний секретний ключ (shared secret), відомий лише відправнику та одержувачу:

- Якщо зловмисник підмінить повідомлення й залишить старий MAC, перевірка через `hmac.compare_digest()` поверне `False`.
- Згенерувати ж новий коректний MAC для зміненого повідомлення зловмисник не має змоги, оскільки йому невідомий секретний ключ HMAC.

Таким чином, HMAC забезпечує не лише контроль цілісності даних (data integrity), але й автентифікацію джерела повідомлення (message authenticity).
