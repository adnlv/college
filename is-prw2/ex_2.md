# Завдання 2. Підбір пароля за SHA-256

1. візьміть «Цільовий SHA-256» зі свого варіанта. Невідомий пароль належить простору кандидатів із розділу “Набір спільних даних”;
2. реалізуйте власний словниково-комбінаторний перебір 3600 кандидатів за встановленим порядком;
3. для кожного кандидата обчисліть SHA256(UTF8(candidate)) та порівняйте з цільовим хешем;
4. після знаходження збігу збережіть знайдений пароль, номер спроби та час пошуку, виміряний за допомогою time.perf_counter();
5. окремо виміряйте середній час одного SHA-256 за 100 000 обчислень (за потреби повторіть вимірювання 3 рази). Обчисліть кількість обчислень за секунду.

## Результат виконання

```text
Matching password: kernel04
Found on attempt: 1705
Elapsed time: 0.001431 (sec)

Run 1: 0.000000149 seconds
Run 2: 0.000000151 seconds
Run 3: 0.000000152 seconds
```

## Таблиця швидкодії SHA-256

| Замір | Час 100 000 обчислень (сек) | Середній час одного хешу (сек) | Кількість обчислень за секунду (хешрейт) |
| :---: | :---: | :---: | :---: |
| Run 1 | 0.0149 | 0.000000149 (149 нс) | ~6.71 млн / сек |
| Run 2 | 0.0151 | 0.000000151 (151 нс) | ~6.62 млн / сек |
| Run 3 | 0.0152 | 0.000000152 (152 нс) | ~6.58 млн / сек |
| **Середнє** | **0.01507** | **~0.000000151 (151 нс)** | **~6.64 млн / сек** |

## Пояснення

1. **Аналіз результатів словникового перебору (п. 1–4):**
   - Простір пошуку складався з 36 базових слів (4 групи по 9 слів) та 100 двозначних числових суфіксів (`00`–`99`), утворюючи комбінаторний простір обсягом 36 × 100 = 3600 кандидатів.
   - Відповідний пароль `kernel04` було успішно знайдено на **1705-й спробі**. Оскільки слово `kernel` є 18-м у встановленому порядку, алгоритм перебрав 17 × 100 = 1700 попередніх варіантів та 5 варіантів суфіксів (`kernel00`..`kernel04`).
   - Повний час пошуку склав лише **0.001431 с** (~1.43 мілісекунди) на звичайному процесорі.

2. **Швидкодія та продуктивність SHA-256 (п. 5):**
   - За результатами вимірювання за допомогою `timeit.repeat` середній час одного обчислення SHA-256 становить приблизно **151 нс** (1.51 × 10⁻⁷ с).
   - Відповідно, швидкість обчислення на одному ядрі CPU в однопотоковому режимі Python досягає:
     `Хешрейт = 1 / (1.507 × 10⁻⁷ с) ≈ 6.64 × 10⁶ хешів/с (близько 6.64 млн хешів за секунду)`

3. **Чому "чистий" SHA-256 непридатний для зберігання паролів:**
   - **Орієнтація на максимальну швидкість (Fast Hash):** Алгоритм SHA-256 спроєктовано для швидкого гешування великих потоків даних (перевірка цілісності файлів, мережевих пакетів тощо). Для зберігання паролів висока швидкість є критичним недоліком, оскільки дозволяє зловмисникові здійснювати масовий перебір.
   - **Вразливість до апаратного зламу (GPU / FPGA / ASIC):** Оскільки SHA-256 базується на простих 32-бітних арифметичних і логічних операціях та не вимагає виділення оперативної пам'яті (працює суто в регістрах), сучасні відеокарти (GPU) здатні обчислювати десятки мільярдів хешів на секунду (> 10¹⁰ хешів/с), а спеціалізовані ASIC-чипи — трильйони.
   - **Небезпека для паролів із низькою ентропією:** Навіть простір у кілька десятків мільйонів чи мільярдів комбінацій зловмисник зламує майже миттєво.
   - **Відсутність регулятора складності (Work Factor):** У SHA-256 неможливо налаштувати складність обчислень зі зростанням потужності апаратного забезпечення. Для захисту паролів сучасні стандарти (OWASP) вимагають застосування спеціальних повільних, пам'ятезатратних (memory-hard) функцій формування ключа (KDF), таких як Argon2id, bcrypt або scrypt.
