# Завдання 5. bcrypt: сіль і параметр cost

1. використайте пароль, знайдений у завданні 2, і створіть два bcrypt-хеші одного пароля при cost = 10. Порівняйте рядки: чому вони відрізняються?
2. перевірте правильний пароль і явно неправильний пароль (наприклад, password + "X") функцією bcrypt.checkpw();
3. виміряйте час хешування при cost = 10, 11, 12. Для кожного значення виконайте хоча б 2 незалежні вимірювання;
4. складіть таблицю часу й поясніть, як збільшення cost впливає на швидкість підбору.

## Пояснення

1. **Чому два bcrypt-хеші одного пароля відрізняються (п. 1):**
   Функція `bcrypt.gensalt(rounds=10)` при кожному виклику генерує нову унікальну випадкову 128-бітну сіль (salt). Навіть для однакового пароля (`kernel04`) та однакового параметра `cost=10` підсумкові хеші виходять абсолютно різними, що захищає від атак за попередньо обчисленими таблицями (Rainbow tables) та унеможливлює виявлення однакових паролів у різних користувачів. Сама сіль і параметр cost автоматично зберігаються на початку результуючого рядка хешу (префікс `$2b$10$...`), тому `bcrypt.checkpw()` успішно валідує пароль без потреби окремого збереження солі.

2. **Вплив збільшення `cost` на швидкість підбору (п. 4):**
   Параметр `cost` задає логарифмічну складність: кількість раундів розширення ключа становить 2^cost.

   - Збільшення `cost` на одиницю подвоює кількість обчислень і, відповідно, подвоює час хешування (експоненційне зростання ~ 0.055 → 0.107 → 0.214 с).
   - Для звичайного користувача затримка в 0.1–0.2 с є невідчутною при автентифікації.
   - Для зловмисника, що проводить офлайн-перебір (brute-force), кожен крок збільшення `cost` удвічі знижує кількість можливих спроб за одиницю часу на тому ж обладнанні. Це робить масовий перебір паролів надзвичайно ресурсомістким та економічно невигідним.
