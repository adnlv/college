# Контрольні запитання та відповіді

## 1. Які етапи треба виконати для підключення по SSH без паролю?

1. **Генерація пари SSH-ключів на клієнті (PC1):**
   Виконати команду `ssh-keygen -t rsa` (або `ssh-keygen -t ed25519`), у результаті чого у `~/.ssh/` створюються два файли: приватний ключ (`id_rsa`) та публічний ключ (`id_rsa.pub`).
2. **Передача публічного ключа на сервер (PC2):**
   Скопіювати файл `id_rsa.pub` на віддалений хост (через `scp`, `ssh-copy-id` або іншим способом).
3. **Авторизація публічного ключа на сервері (PC2):**
   Додати вміст публічного ключа до файлу `~/.ssh/authorized_keys` потрібного користувача на сервері та переконатися у коректних правах доступу (`chmod 700 ~/.ssh` і `chmod 600 ~/.ssh/authorized_keys`).
4. **Перевірка конфігурації `sshd` (за потреби):**
   Переконатися, що на сервері у `/etc/ssh/sshd_config` увімкнено автентифікацію за ключами (`PubkeyAuthentication yes`) та працює демон `sshd`.
5. **Підключення:**
   Виконати `ssh <user>@<host>` — клієнт пройде автентифікацію асиметричним криптографічним підписом без введення пароля облікового запису (якщо приватний ключ не захищено окремою passphrase або вона завантажена в `ssh-agent`).

## 2. Якою командою `systemctl` ви перевірите поточний стан сервісу `cron`?

Команда залежить від конкретного дистрибутиву Linux та встановленого планувальника (`cronie` у Arch/CachyOS/RHEL/Fedora або `cron` у Debian/Ubuntu):

```bash
systemctl status crond
```

(або `systemctl status cronie` на Arch-подібних системах / `systemctl status cron` на Debian/Ubuntu).

Для перевірки лише статусу активності без детального виводу також використовують:

```bash
systemctl is-active crond
```

## 3. Яка команда дозволяє перевірити логи системного сервіса?

Для перегляду журналів системних сервісів, керованих `systemd`, використовується утиліта `journalctl` із прапорцем `-u` (`--unit`):

```bash
journalctl -u <назва_сервісу>
```

Наприклад:
- `journalctl -u sshd` — перегляд логів демона SSH;
- `journalctl -u crond` (або `journalctl -u cronie`) — перегляд логів планувальника `cron`;
- корисні додаткові прапорці: `-n 50` (останні 50 рядків), `-f` (відстеження у реальному часі), `--since "10 minutes ago"` (за останні 10 хвилин).

## 4. У чому полягає ключова перевага автентифікації за SSH-ключами у порівнянні з автентифікацією за паролем?

**Ключова перевага — значно вищий рівень криптографічної стійкості та відсутність передачі секрету мережею:**

- **Стійкість до підбору (brute-force):** SSH-ключі (наприклад, RSA 2048–4096 біт або Ed25519) мають незрівнянно більшу ентропію, ніж паролі користувачів, що робить перебір практично неможливим.
- **Приватний ключ ніколи не покидає клієнта:** під час рукостискання сервер перевіряє володіння приватним ключем через криптографічний виклик-відповідь (challenge-response) за допомогою публічного ключа, тому навіть скомпрометований сервер або перехоплення трафіку не розкриває сам приватний ключ.
- **Безпечна автоматизація:** ключі (разом з `ssh-agent` або обмеженими ключами) дозволяють безпечно автоматизувати сценарії, резервне копіювання (`scp`/`rsync`) та CI/CD без зберігання паролів у відкритому вигляді.

## 5. Які параметри необхідні для створення SSH тунелю?

Залежно від типу SSH-тунелю (прямий локальний, зворотний або динамічний SOCKS-проксі) використовуються такі основні параметри команди `ssh`:

1. **Тип тунелювання та адресація портів/хостів:**
   - `-L [bind_address:]local_port:target_host:target_port` — **локальне перенаправлення (Local Port Forwarding)**: відкриває порт на клієнті та перенаправляє трафік через SSH-сервер на `target_host:target_port`.
   - `-R [bind_address:]remote_port:target_host:target_port` — **зворотне перенаправлення (Remote Port Forwarding)**: відкриває порт на віддаленому SSH-сервері та перенаправляє підключення назад на клієнта або в його локальну мережу.
   - `-D [bind_address:]local_port` — **динамічне перенаправлення (SOCKS4/SOCKS5 проксі)** на вказаному локальному порту.
2. **Обов'язкові параметри SSH-з'єднання:**
   - `<user>@<ssh_server_host>` — ім'я користувача та адреса SSH-сервера, через який прокладається тунель.
3. **Корисні додаткові прапорці керування сесією:**
   - `-N` — не виконувати віддалену команду / не відкривати інтерактивну оболонку (використовувати з'єднання лише для перенаправлення портів);
   - `-f` — перевести `ssh` у фоновий режим перед виконанням тунелю;
   - `-p <ssh_port>` — вказати нестандартний порт SSH-сервера (якщо не 22);
   - `-i <identity_file>` — шлях до приватного ключа для автентифікації.

**Приклад локального тунелю:**

```bash
ssh -N -L 8080:127.0.0.1:80 user@192.168.1.50
```
